# Lua 自动化发现层迁移清单

`参考源码_需项目适配` 展示的是一个可工作的设计：扫描 `Content/TestScript/Test/*.lua`，从函数前缀决定测试类型，再委托 UE Automation Framework 执行。

## 需要替换的项目依赖

| 参考源码中的依赖 | 作用 | 目标项目处理方式 |
| --- | --- | --- |
| `EMEDITOR_API` | 原模块导出宏 | 替换为目标 Editor 测试模块的 API 宏 |
| `ULuaEnvLocator` / `UnLua` | 获取 Lua 主虚拟机 | 接入同等 Lua 运行时；不使用 Lua 则删除整层 |
| `FClientFunctionalTestingMapsBase` | 项目自定义的地图测试基类 | 改为项目自己的基类，或直接基于 UE `FAutomationTestBase` 实现地图打开与等待 |
| `BP_FunctionalTestActor` 固定路径 | 在目标地图中生成并驱动功能测试 | 创建项目自己的 Blueprint Actor，并把路径改为配置项 |
| `Content/TestScript/Test` | Lua 测试文件根目录 | 改为项目测试脚本目录，建议经 Developer Settings 配置 |
| `EMTest` | Automation 面板中的测试前缀 | 改为 `项目名.Automation`，便于过滤 |

## Lua 用例约定

```lua
local Test = TestClass("/Game/Maps/TestMap")

function Test:UTest_InventoryMath()
  -- UTest_ 前缀：无需地图的单元测试
end

function Test:FTest_OpenChest()
  -- FTest_ 前缀：需要打开地图并由 Functional Test Actor 驱动
end

return Test
```

## 接入验收

- Editor 启动后可发现至少一个 `UTest_` 和一个 `FTest_`。
- 单元测试失败时，Automation 面板显示明确断言或 Lua 异常。
- 功能测试能打开指定地图、等待 Actor 初始化并正确结束。
- 缺少地图、蓝图或 Lua 函数时，测试应失败并输出错误，而不是静默通过。
- 在干净工作区连续运行两次，结果一致且不残留测试数据。
