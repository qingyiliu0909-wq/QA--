# 游戏 QA 工具箱

本目录收录可跨项目复用的 QA 工具源码与模板。目录统一使用 **`中文用途（原工具名）`** 命名，方便识别，同时保留原工具名以便搜索和追溯。

未收录当前项目的玩法配置、数值、测试截图、历史报告、内部服务地址、账号配置和业务专用校验规则。

## 01 自动化跑测

| 工具包 | 用途 | 迁移时需要做的事 |
|---|---|---|
| `黑盒自动化跑测框架（runner）` | 在 Windows 或 Android 真机上通过图像/控件定位执行黑盒流程，输出截图、日志、JSON 和 JUnit 报告。 | 配置游戏进程/包名、创建 YAML 用例与图片锚点。 |

## 02 配置与静态检查

| 工具包 | 用途 | 迁移时需要做的事 |
|---|---|---|
| `跨表配置检索（config-searcher）` | 读取 Excel/CSV，按 `XXId` 命名约定自动追踪外键和跨表引用。 | 在 `config.json` 补充字段中文含义、枚举和值展示规则。 |
| `资源命名规范校验（asset-naming-checker）` | 用 JSON 规则检查 Unreal 资源的前后缀和命名一致性。 | 修改 `DefaultAssetNamingRules.json` 为目标项目资产规范。 |
| `着色器静态分析（shader-static-analysis）` | 对 HLSL/Shader 做静态结构分析。 | 安装 `requirements.txt` 依赖并确认项目 Shader 语法兼容。 |

## 03 需求与文档质量

| 工具包 | 用途 | 迁移时需要做的事 |
|---|---|---|
| `文档交叉检查核心（doc-crosscheck-core）` | 把交互、系统等多份文档抽取为结构化信息并生成冲突报告。 | 配置文档来源、受控词表和认证方式；不含任何项目专用 UI 标准卡。 |

## 04 测试用例工具

| 工具包 | 用途 | 迁移时需要做的事 |
|---|---|---|
| `大纲转换OPML（outline-to-opml）` | 将需求/测试点大纲转成可导入脑图的 OPML。 | 按本团队的大纲格式提供输入。 |
| `OPML层级规范化（normalize-opml-outline-levels）` | 清理和统一 OPML 脑图的层级。 | 直接对导出的 OPML 执行。 |

## 05 工作流模板

| 工具包 | 用途 | 迁移时需要做的事 |
|---|---|---|
| `工作流质量检查模板（workflow-quality-templates）` | 检查工作流的目录、链接、范围、冗余、可执行性和复用性。 | 按团队实际工作流路径替换引用。 |

## 未纳入的候选

- `Uauto/`：依赖项目自动化插件、内部服务和账号体系。
- `Json/` 与 `docs/`：属于具体产品知识和配置资产。
- `config_validator`：当前只支持本项目的 Lua 导表、DynQuest、Dispatch、Fishing 规则，需重构后才适合独立发布。
- `Tools/doc_crosscheck/standards/`：包含当前项目 UI API、路径和控件行为契约。
- `TestCases/`：用例生成机制可参考，但输入数据绑定当前玩法。
