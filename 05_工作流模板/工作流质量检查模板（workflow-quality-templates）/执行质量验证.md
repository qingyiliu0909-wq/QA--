# 执行质量验证

## 本步目标

验证工作流执行结果是否符合质量标准，输出是否完整、规范。

## 执行前必读

- [[../专项知识/01_验证核心/Repo扩展专项_工作流设计原则]]
- 目标工作流的输出规范

## 必需输入

- 工作流执行结果目录
- 预期的输出规范

## 建议动作

1. 检查目录结构是否符合规范
2. 检查必需文件是否存在
3. 检查文件内容是否完整
4. 检查数据质量（如 JSON 格式正确）
5. 检查报告质量（是否有结论、证据、方案）

## 验证清单

| 检查项 | 合格标准 |
|--------|----------|
| 目录结构符合规范 | 按输出规范创建 |
| 必需文件存在 | 所有必需文件已生成 |
| 文件内容完整 | 无空文件或占位符 |
| 数据格式正确 | JSON/YAML 可解析 |
| 报告有结论 | 每个结论有数据支撑 |

## 质量分级

| 级别 | 条件 |
|------|------|
| P0-阻塞 | 缺少核心交付物 |
| P1-严重 | 数据不完整或格式错误 |
| P2-一般 | 内容质量待改进 |
| P3-建议 | 可选优化项 |

## 产出物

- 质量验证报告
- 问题清单（分级）
- 改进建议

## 完成证据

- [ ] 已检查目录结构
- [ ] 已检查文件完整性
- [ ] 已检查数据质量
- [ ] 已检查报告质量
- [ ] 已生成分级问题清单

## 失败自愈入口

- 若缺少必需文件 → 提示重新执行对应步骤
- 若数据格式错误 → 提示修复格式
- 若报告不完整 → 提示补充缺失内容
