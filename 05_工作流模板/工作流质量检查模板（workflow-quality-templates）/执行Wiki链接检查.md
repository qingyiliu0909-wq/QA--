# 执行Wiki链接检查

## 技能依赖

本步骤调用以下原子能力:
- **workflow_scanner**: Wiki链接健康检查（v4.0）

## 本步目标

检查Wiki链接健康状态，识别真死链和路径问题，确保Obsidian链接可解析。

## 必需输入

- 扫描路径（默认：.worker/.wiki/）
- 或指定工作流路径

## 执行流程

### 1. 调用workflow_scanner技能

```powershell
python ".worker/.skill/工具类/Agent Repo/workflow_scanner/scripts/repo_task_tool_v2.py" <scan_path> --json report.json --md report.md
```

### 2. 分析扫描结果

读取JSON报告，提取关键指标：
- 正常链接数量
- 路径问题数量
- 真死链数量

### 3. 分类链接状态

根据最佳实践规范分类：

| 状态 | 判断标准 | 处理优先级 |
|------|---------|----------|
| OK | 路径正确，文件存在 | 无需处理 |
| PATH_ISSUE | 文件存在但路径不规范 | P2（可选修复） |
| DEAD_LINK | 文件不存在（真死链） | P1（必须处理） |

### 4. 生成问题清单

对每个问题链接，记录：
- 源文件路径
- 行号
- 链接内容
- 目标文件（如存在）
- 问题类型

## 产出物

- Wiki链接扫描报告（JSON格式）
- Wiki链接扫描报告（Markdown格式）
- 问题链接清单
- 修复建议

## 完成证据

- [ ] 已调用workflow_scanner技能
- [ ] 已生成扫描报告
- [ ] 已识别问题链接
- [ ] 已分类链接状态

## 失败自愈入口

- 若扫描失败 → 检查Python环境和脚本路径
- 若无权限 → 检查文件访问权限
- 若路径不存在 → 提示确认扫描路径

## 链接最佳实践规范

本步骤应用以下最佳实践：

### 核心原则
```
可读性 > 精确性 > 简洁性

原则1：路径深度 ≤ 3层
原则2：优先使用文件名（如果唯一）
原则3：跨类别必须使用路径
原则4：避免../../多层回退
```

### 推荐策略

#### 1. 文件名优先（如果唯一）
```markdown
✅ [[Superpowers统一架构原则]]
✅ [[Repo扩展专项_工作流设计原则]]
```

#### 2. 跨类别加路径
```markdown
✅ [[知识/Superpowers统一架构原则]]
⚠️ [[工作流/Repo扩展专项/WORKFLOW]]（路径较长，可接受）
```

#### 3. 避免深层相对路径
```markdown
❌ [[../../知识/xxx]]
✅ [[知识/xxx]]
```

### 命名规范
```markdown
✅ Repo扩展专项_工作流设计原则.md（自解释）
✅ 性能与稳定性_代码路径速查.md（自解释）
❌ 原则.md（缺乏上下文）
❌ 速查.md（缺乏上下文）
```
