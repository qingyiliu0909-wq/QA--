# 验证目录结构

## 本步目标

验证工作流的目录结构是否符合统一架构规范，确保AI和人类双向友好。

## 必需输入

- 工作流类别路径（如 `工作流/性能与稳定性/`）
- 或单个工作流路径

## 验证清单

### 1. 必需目录检查

| 检查项 | 路径示例 | 合格标准 |
|--------|----------|----------|
| 共享库 | `00_共享库/` | 存在 |
| 标准步骤 | `00_共享库/标准步骤/` | 存在 |
| 专项知识 | `00_共享库/专项知识/` | 存在 |
| 类别索引 | `_INDEX.md` | 存在 |

### 2. 层级深度检查

| 检查项 | 合格标准 | 不合格示例 |
|--------|----------|------------|
| 最大层级 | ≤ 5 层 | `A/B/C/D/E/F.md` |
| 文件名信息 | 自带完整上下文 | `common.md` |

### 3. 命名规范检查

| 类型 | 命名格式 | 不合格示例 |
|------|----------|------------|
| 知识文档 | `<类别名>_<内容>.md` | `踩坑经验.md` |
| 步骤文档 | `<动词>_<对象>.md` | `step1.md` |
| 工作流文档 | `WORKFLOW.md` | `workflow.md` |

### 4. 禁止项检查

| 禁止项 | 原因 |
|--------|------|
| `common/` 目录 | 对AI检索不友好 |
| `problems/` 目录 | 通用词，命中率低 |
| 深层嵌套（>5层） | RAG切片丢失上下文 |

## 验证流程

```
1. 读取目录结构
2. 遍历每个检查项
3. 记录合格/不合格项
4. 生成验证报告
```

## 产出物

- 目录结构验证报告（JSON格式）
- 不合格项清单
- 修复建议

## 完成证据

- [ ] 已检查必需目录
- [ ] 已检查层级深度
- [ ] 已检查命名规范
- [ ] 已生成验证报告

## 失败自愈入口

- 若缺少`00_共享库/` → 提示创建目录
- 若缺少`_INDEX.md` → 提示创建索引文件
- 若层级过深 → 提示扁平化建议
