# 执行路由验证

## 本步目标

验证工作流的关键词能否被 Superpowers 正确命中。

## 必需输入

- 工作流元数据（name, keywords）
- 测试样例列表（用户请求 → 期望工作流）

## 测试样例构造方法

### 方法1：从关键词构造

从工作流的 keywords 字段提取关键词，构造测试样例：

```yaml
工作流：性能分析
keywords: [性能分析, UTrace, 卡顿, 完整流程]

测试样例：
- 样例1："分析性能问题" → 性能分析
- 样例2："UTrace 卡顿分析" → 性能分析
- 样例3："完整性能流程" → 性能分析
```

### 方法2：从案例库提取

从 `.worker/.wiki/Repo扩展专项/案例库/` 中提取成功案例的用户请求：

```yaml
案例：yiwei_new_workflow_20260714.md
用户请求："分析一下 yiwei.utrace 的性能问题"
期望工作流：性能分析
```

### 方法3：用户提供

用户可以提供自定义测试样例。

## 验证流程

```
for each 样例:
    1. 提取关键词
    2. 执行路由匹配：
       a. 读取路由表
       b. 匹配类别
       c. 读取类别索引
       d. 匹配工作流
    3. 对比期望结果
    4. 记录结果
```

## 验证指标

- **命中率**：正确命中的样例数 / 总样例数
- **误命中**：命中错误工作流的样例数
- **未命中**：未能命中的样例数

## 质量门禁

- ✅ 命中率 ≥ 80%：合格
- ⚠️ 命中率 50-80%：需改进
- ❌ 命中率 < 50%：不合格

## 产出物

- 路由验证报告（JSON 格式）
- 失败样例清单
- 路由改进建议

## 完成证据

- [ ] 已构造测试样例（至少3个）
- [ ] 已执行路由匹配
- [ ] 已记录命中率
- [ ] 已生成验证报告

## 失败自愈入口

- 若命中率不足 → 分析失败样例，调整关键词
- 若路由表缺失 → 提示创建路由表
- 若类别索引缺失 → 提示创建类别索引
