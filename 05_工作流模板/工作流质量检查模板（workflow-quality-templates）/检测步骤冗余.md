# 检测步骤冗余

## 本步目标

检测工作流中的冗余步骤、空洞步骤、重复步骤，确保流程精简高效。

## 必需输入

- 工作流WORKFLOW.md文件
- 或工作流路径

## 检测维度

### 1. 重复输入检测

**检测方法**：统计每个步骤的"必需输入"，发现重复。

```yaml
示例：
步骤A必需输入：[UTrace文件, 配置文件]
步骤B必需输入：[UTrace文件, 配置文件]
→ 步骤A和B存在重复输入
```

**处理建议**：合并为前置输入步骤，或在一处声明后共享。

### 2. 重复输出检测

**检测方法**：统计每个步骤的"产出物"，发现重复。

```yaml
示例：
步骤A产出：[子系统数据]
步骤C产出：[子系统数据]
→ 步骤C可能冗余
```

**处理建议**：删除后续重复步骤，或改为引用前置输出。

### 3. 无效步骤检测

**检测方法**：检查步骤产出是否被后续步骤使用。

```yaml
示例：
步骤A产出：[临时文件]
步骤B、C、D均不使用"临时文件"
→ 步骤A产出未被使用，可能冗余
```

**处理建议**：确认是否真的不需要，若不需要则删除或修改产出。

### 4. 空洞步骤检测

**检测方法**：检查步骤描述是否有实质内容。

```yaml
示例：
步骤B："然后进行分析"
→ 缺少具体动作、输入、输出，为空洞步骤
```

**处理建议**：补充具体内容，或合并到相邻步骤。

## 检测流程

```
1. 解析工作流文件
2. 提取所有步骤的输入/输出
3. 构建数据流图
4. 检测4种冗余类型
5. 生成冗余报告
```

## 冗余判定标准

| 冗余类型 | 判定条件 | 严重程度 |
|----------|----------|----------|
| 重复输入 | ≥2个步骤要求相同输入 | 中 |
| 重复输出 | ≥2个步骤产出相同内容 | 高 |
| 无效步骤 | 产出不被任何后续步骤使用 | 高 |
| 空洞步骤 | 缺少输入/输出/动作描述 | 高 |

## 产出物

- 步骤冗余检测报告
- 冗余类型统计
- 修复建议（合并/删除/补充）

## 完成证据

- [ ] 已解析工作流步骤
- [ ] 已构建数据流图
- [ ] 已检测4种冗余类型
- [ ] 已生成修复建议

## 失败自愈入口

- 若步骤描述不完整 → 标注为"待补充"
- 若数据流断裂 → 提示添加数据传递步骤
- 若无法判断 → 标注为"需人工确认"
